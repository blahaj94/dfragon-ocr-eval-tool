# 자료실 모델로 학습하고 평가하기

미니PC의 `ocr.dfragon.com`이 모델 파일과 OCR 데이터를 보관합니다. Windows 앱은 로그인 후 REST API로 선택한 모델·데이터를 가져와 이 PC의 GPU로 학습하고 평가합니다. 사용자가 **미니PC에 올리기**를 누르면 새 모델과 평가 요약을 등록합니다.

## 사용 순서

1. 모델 보관 API가 포함된 dfragon OCR 서버를 먼저 배포합니다. 웹의 **학습 모델 → 기본 한국어 PP-OCRv5 모델 추가**로 첫 모델을 등록합니다. 공식 학습 가중치와 문자 사전을 미니PC에 보관하며, 기존 모델을 덮어쓰지 않습니다.
2. 자료실의 **자동 분할**에서 실제 이미지·고유 닉네임·문자 분포를 보고 원하는 train/val/test 규모를 입력합니다. 정해진 기본 비율은 없습니다. 미리보기는 읽기만 하며, **적용**으로 확정합니다. 기존 배정은 기본적으로 유지하며 재배정은 명시적으로 선택해야 합니다. 같은 NFC 닉네임은 같은 분할을 사용합니다.
3. Windows 앱의 **학습** 탭에서 **자료실 로그인**을 누르고 기존 패스키로 로그인합니다. 시작 모델과 실험 저장 폴더를 선택해 **모델·데이터 가져오기**를 누릅니다.
4. 앱은 목록 조회 시점의 정답·분할과 선택한 이미지·모델을 새 `experiment-UUID` 폴더에 저장합니다. 정답 완료·미제외·배정된 샘플만 사용하며 나머지 개수를 표시합니다. 세 분할에 각각 한 개 이상의 샘플이 필요합니다.
5. **Train 문자 구성**에서 실제 문자 빈도와 사전 밖 문자를 확인합니다. 필요한 문자만 사전에 추가하고, 합성을 사용할 때는 아래 순서대로 목표·문자 목록·폰트·배경을 정해 미리보기합니다. **학습 실행 환경**에서 GPU Python과 PaddleOCR 소스를 선택합니다. 기존 평가 설정의 학습 환경이 있으면 초기값으로 사용합니다. 학습 횟수·배치 크기·학습률을 확인하고 **학습 후 test 평가**를 누릅니다.
6. 실제 train 전체와 이번 실행의 합성 train으로 학습하고 매 epoch마다 실제 val을 평가합니다. CER가 가장 낮은 가중치를 선택하며, 같으면 Exact Match가 높은 가중치를 선택합니다. 둘 다 같으면 먼저 저장한 것을 유지합니다. 선택한 가중치를 다시 불러와 실제 test를 한 번 평가합니다.
7. CER·Exact Match·정답과 예측·오답 이미지를 확인합니다. 이름을 입력하고 **미니PC에 올리기**를 누르면 가중치·사전·평가 요약이 새 모델 ID로 등록됩니다. 다음 학습의 시작 모델로 선택할 수 있습니다.

학습 중 취소는 현재 GPU 연산 뒤에 반영됩니다. 취소·실패 결과에 최종 성적을 표시하지 않습니다. 다운로드와 학습 파일은 지우지 않습니다. 새로운 학습 실행은 항상 새로운 `runs/UUID` 폴더를 사용합니다.

**저장한 실험·결과 열기**에서 실험 폴더를 선택하면 같은 입력으로 새 학습을 시작할 수 있습니다. 완료된 `runs/UUID`를 선택하면 앱 재시작 후에도 성적·이미지를 확인하고 등록할 수 있습니다. 등록 응답이 끊겼다면 같은 이름으로 다시 시도하세요. 저장된 등록 ID를 재사용하므로 중복 모델을 만들거나 기존 모델을 덮어쓰지 않습니다. 중단된 epoch부터 재개하거나 평가만 재실행하는 기능은 이번 버전에 포함하지 않습니다.

자료실에서 최초 분할을 적용한 이후, 새 캡처가 기존 닉네임이면 그 분할을 따릅니다. 새 닉네임은 정답 저장 후 train에 배정됩니다. 기존 닉네임을 자동으로 이동시키지 않으며 수동 미배정도 보존합니다. 매주 자료를 추가하더라도 내려받은 실험 입력은 바뀌지 않습니다. 새 실제 자료를 포함하려면 다시 가져오세요. 기존 val/test 닉네임의 새 이미지가 서버에 추가되면 다음 가져오기에 포함됩니다.

## 목표 분포와 합성 보충

비율의 분모는 **실제+합성 train 정답의 문자 수**입니다. `검사★龍`은 한글 2개·특수문자 1개·한자 1개입니다. 한글·특수문자·히라가나·가타카나·한자·영문/라틴·숫자·기타를 따로 집계합니다. 화면과 Python 모두 Unicode Script를 우선 사용합니다. 예를 들어 CP949의 `ⓐ`·`⒜`는 특수문자, `Ⅰ`·`ⅰ`는 라틴으로 집계합니다.

1. **부족한 문자군을 합성으로 보충**을 켭니다. 보충할 문자군의 목표 비율과 사용할 문자 목록을 입력합니다. 목표가 빈 문자군은 목표 검사에서 빠지고, 문자 목록이 빈 문자군은 합성하지 않습니다. 희귀 기호나 한자를 자동으로 모두 선택하지 않습니다.
2. 허용 오차를 직접 `%p`로 입력합니다. 예를 들어 목표 10%, 오차 1%p이면 가능한 최소 보충량을 9%부터 계산합니다. 다른 문자군 보충으로 전체 문자 수가 늘어나는 효과도 반영합니다. 실제 자료를 줄이지 않으므로 낮출 수 없는 목표는 차이와 경고로 표시합니다. 목표 합계 100% 초과 등 입력 오류와 달리, 목표 미달·조합 부족·상한 도달만으로 실행을 막지 않습니다.
3. 합성용 Python과 로컬 폰트 경로를 선택합니다. 크롭 크기는 실제 train의 중앙값에서 시작합니다. 배율·크기·여백·글자 색을 실제 UI에 맞춥니다. 글자가 잘리면 실행 오류로 알립니다.
4. 일정한 UI는 배경 색을, 장면이 비치는 UI는 **글자가 없는** 불투명 PNG/JPEG 폴더를 선택합니다. 배경 조각은 크롭 이상 크기여야 합니다. 닉네임마다 배경과 자를 위치를 고르며 모든 닉네임×배경 조합을 복제하지 않습니다.
5. **보충량 계산·합성 미리보기**로 실제 분포, 보충 이미지·문자 수, 최종 예상 분포, 목표와의 차이와 최대 6개 예시를 봅니다. 설정을 바꾸면 다시 미리보기합니다. 학습 시작 시 전체 합성 이미지를 새 run 안에서 생성합니다. 취소하면 GPU 학습을 시작하지 않습니다.

합성기는 [dnf-ocr-synth 0.1.2](https://github.com/blahaj94/dnf-ocr-synth/tree/809df79c95cffb2d315f56cf14294c83d912ce89)를 사용합니다. 선택한 문자 안에서 등장 빈도가 낮은 문자를 우선하고 닉네임 안의 같은 문자 반복과 닉네임 중복을 피합니다. 현재 실제 train/val/test의 모든 NFC 정답 닉네임을 합성 후보에서 제외합니다. CP949 왕복 가능·최대 12바이트·공백/비가시 문자 금지 등 합성기의 게임 닉네임 규칙을 그대로 적용합니다. 작은 문자 목록으로 다양성을 확보할 수 없으면 경고와 실제 생성량을 표시합니다.

합성 PNG는 투명 RGBA 글자를 선택한 배경에 alpha composite한 **RGB 불투명 이미지**입니다. 기존 투명 이미지 거절 검사는 유지합니다. 현재 PaddleOCR DecodeImage는 3채널 색상으로 읽으므로 알파를 버리며, 자동 흰 배경이나 투명 영역 무시는 기대하지 않습니다. 별도 detection이나 전체 게임 화면 생성은 하지 않습니다.

합성 설정을 달리하는 실험은 같은 실험 폴더에서 새 run으로 시작합니다. 매번 실제 자료에서 다시 계산하며 이전 합성 자료를 누적하지 않습니다. 실제 자료가 늘면 필요한 합성량은 문자 구성에 따라 줄거나 늘 수 있습니다. 저장된 run을 열면 그 실행의 목표·오차·문자 추가·합성 예시를 확인할 수 있으며 전체 사용 입력은 `input.json`에 있습니다. 서버에 영구 평가 묶음이나 새 데이터셋 버전 관리 시스템을 만들지 않습니다.

## 로컬 합성 환경 준비

GPU 학습 환경의 Pillow 11.3과 합성기가 요구하는 Pillow 12.3 이상을 분리합니다. Windows PowerShell에서 별도 Python 3.12 가상환경을 만들고, 앱의 **합성용 Python**에 그 실행 파일을 선택하세요. 다음 명령은 Git이 설치되어 있다고 가정합니다.

```powershell
py -3.12 -m venv .venv-synth
& .\.venv-synth\Scripts\python.exe -m pip install "dnf-ocr-synth @ git+https://github.com/blahaj94/dnf-ocr-synth@809df79c95cffb2d315f56cf14294c83d912ce89" "regex==2026.9.10"
```

GPU 학습 Python에도 문자군 검증용 `regex==2026.9.10`을 추가합니다. GPU 환경의 Pillow는 바꾸지 않습니다. 예: 해당 환경을 활성화한 뒤 `python -m pip install "regex==2026.9.10"`.

폰트는 배포 파일이나 서버에 올리지 않습니다. 돋움 모드는 `gulim.ttc`, 한자·일부 대체 글꼴은 `batang.ttc`, 돋움의 영문 `I`는 로컬 으뜸체가 필요합니다. 나눔 모드는 `NanumSquareNeoOTF-cBd.otf`를 선택합니다. 선택한 문자의 실제 폰트 coverage를 미리 검사하며 없는 글리프를 다른 문자로 바꾸지 않습니다. 실제 UI와 글꼴·테두리·배율이 맞는지는 미리보기로 확인하세요.

## 문자 확장 모델

기본 한국어 사전에 없는 문자는 **모델에 추가할 문자**에 명시적으로 넣습니다. 기존 순서를 유지하며 새 문자를 끝에 한 번씩 추가합니다. 실제 정답을 변경하거나 삭제하지 않습니다. 실제 정답에 사전 밖 문자가 남으면 해당 문자와 코드포인트를 알리고 학습을 거절합니다. 실제 자료에는 합성기의 CP949 제한을 새로 적용하지 않습니다.

부모 모델의 특징 추출 가중치와 기존 문자 가중치를 보존하고, CTC 출력층 및 NRTR embedding/출력 projection의 새 문자 부분만 초기화합니다. 기존 blank·시작/종료·space·예약 토큰의 대응도 유지합니다. 예상하지 못한 parameter 이름/shape 차이는 거절합니다. 학습된 가중치와 확장 사전은 새 run과 별도 `expanded` 모델에 저장합니다. 확장 없이 다시 학습하면 `finetuned`입니다. 확장 모델에서 추가 확장하거나 같은 사전으로 재학습할 수 있습니다.

서버는 `expanded` 모델의 사전이 부모 사전의 순서를 그대로 포함하고 뒤에 문자만 추가했는지 검증합니다. 일반 `finetuned`는 기존과 같이 부모와 동일한 사전만 허용합니다. **확장 모델 등록에는 이 계약을 지원하는 dfragon 서버가 먼저 필요합니다.** 소스 변경·PR 준비는 운영 배포나 모델 등록 실행을 뜻하지 않습니다.

## 지원 모델과 실행 환경

첫 지원 모델은 [공식 Korean PP-OCRv5 mobile recognition](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/text_recognition.en.md)입니다. 임의의 학습 저장소 URL이나 실행 명령을 웹에서 등록하는 기능은 없습니다. 웹은 실제 모델 파일을 보관합니다.

- Windows x64, NVIDIA CUDA GPU, Python 3.12, PATH에서 실행되는 Git.
- 기존 학습 경로에서 검증한 GPU 환경: PaddlePaddle GPU 3.2.2, NumPy 2.2.6, Pillow 11.3.0, PyYAML 6.0.3, OpenCV 4.11.0.86, Albumentations 2.0.8. 이번 버전은 `regex==2026.9.10`도 필요합니다. PaddleOCR의 나머지 학습 의존성도 설치된 기존 환경을 사용합니다. 일반 Python만으로 실행할 수 없습니다.
- PaddleOCR 소스는 `b03f46425e8ff4442b268ce449e3eef758146cd4`로 고정하며 tracked 파일이 수정된 checkout은 거절합니다. 소스와 GPU 환경을 앱이 자동 설치하지 않습니다.
- 공식 한국어 설정의 MultiHead·MultiLoss, Adam, seed 42, gradient clipping 5를 사용합니다. 기본값은 10 epochs, batch 8, learning rate 0.00001입니다.
- 전처리는 공식 Eval 변환인 BGR·resize/padding `[3,48,320]`을 학습과 평가에 함께 사용합니다. 기본 버전에는 데이터 증강이 없습니다. 기존 평가 탭의 ldb-ocr custom 전처리와 다른 실행 경로입니다.
- 사전의 순서와 가중치의 모든 parameter 이름·shape가 일치해야 합니다. 명시적인 문자 확장은 위 규칙으로만 허용합니다. 확장 후에도 사전에 없는 문자, 25자를 넘는 정답, 투명 PNG는 임의로 고치거나 건너뛰지 않고 거절합니다.

## 고정 입력과 결과

| 파일                                      | 내용                                                               |
| ----------------------------------------- | ------------------------------------------------------------------ |
| `source-manifest.json`                    | 내려받은 시점의 서버 메타데이터 원문                               |
| `dataset.json`, `images/`                 | 선택한 정답·split·이미지 SHA-256·크롭 PNG                          |
| `model/`                                  | 시작 모델의 메타데이터·가중치·사전                                 |
| `ready.json`                              | 다운로드 완료 표시와 dataset 해시                                  |
| `runs/UUID/request.json`, `progress.json` | 실행 설정, epoch별 val 성적과 선택 epoch                           |
| `previews/UUID/`                          | 목표 계산과 최대 6개 합성 미리보기. 학습 입력에 자동 누적하지 않음 |
| `runs/UUID/synthetic/`                    | 해당 실행의 합성 PNG, 설정·분포·폰트/배경 메타데이터와 해시        |
| `runs/UUID/input.json`                    | 실제+합성의 출처·정답·분할·이미지 해시를 담은 사용 입력 목록       |
| `runs/UUID/characters.txt`                | 해당 실행의 문자 순서. 원본 모델 사전은 보존                       |
| `runs/UUID/weights.pdparams`              | val로 선택한 가중치                                                |
| `runs/UUID/report.json`                   | 모든 test 샘플과 성적·실행 환경·코드/가중치 해시                   |
| `runs/UUID/evaluation.json`               | 미니PC에 올리는 요약. 로컬 경로·정답 이미지 원문은 포함하지 않음   |
| `runs/UUID/publish.json`                  | 수동 등록 재시도에 사용하는 동일 ID·이름                           |

모델 파일과 이미지 해시를 검사하고, 학습 중 이미지를 읽을 때도 해시를 재검사합니다. 같은 NFC 닉네임 또는 같은 디코딩 픽셀이 서로 다른 분할에 있으면 중단합니다. 서로 다른 닉네임이 한 캡처에 있다는 이유로 재배정하지 않습니다. 이러한 캡처 혼재는 경고하고 자료실 배정을 유지합니다. 기존 Dataset 탭의 캡처 단위 분할과 구분됩니다.

동일한 test 이미지·정답으로 생성한 완료 보고서 두 개는 기존 **결과 비교** 탭에서 비교할 수 있습니다. test 성적은 epoch 선택에 사용하지 않습니다. 새 자료를 가져오면 새 실험을 생성합니다. 실험 폴더를 옮기면 보고서의 이미지 절대 경로가 바뀌므로 이번 버전은 원래 위치에서 다시 여는 방식을 지원합니다.

## API와 인증

앱 main이 고정 HTTPS 주소와 임시 Electron 세션을 소유합니다. 로그인 창에는 Node 권한과 앱 preload가 없으며 OCR 자료실과 기존 인증 서버의 로그인 경로만 허용합니다. renderer는 토큰·임의 요청 URL을 전달하지 않습니다. 로그인은 앱을 종료하면 유지되지 않습니다.

앱은 owner cookie로 `GET /api/models`, `GET /api/models/:id`, `GET /api/models/:id/files/:name`, `GET /api/export/manifest`, `GET /api/samples/:id/image`를 호출합니다. 수동 등록은 정확한 Origin을 붙인 `POST /api/models` multipart입니다. 서버는 별도로 동일 모델 계약의 Origin 없는 기존 owner Bearer `/api/desktop/models` 경로도 제공합니다. 모델 파일은 합계 128 MiB 이하이며 이름은 `weights.pdparams`, `characters.txt`, `evaluation.json`으로 제한합니다. 등록 파일 해시를 응답과 다시 비교합니다.

## 검증과 한계

기존 사전 그대로의 학습 경로는 합성 PNG와 공식 가중치로 RTX 3080 Ti에서 1 epoch, train 3·val 1·test 1, optimizer 2 steps를 실행해 가중치 저장·재로딩·최종 test 보고서 생성을 확인했습니다. 이는 연결 검증이며 실데이터 정확도나 성능 개선의 증거가 아닙니다.

이번 자동 보충·문자 확장은 로컬 TypeScript/Python 검증, 브라우저/Electron 화면·IPC 검사, 실제 dnf-ocr-synth의 미리보기→불투명 이미지 생성→학습 입력 검증까지 확인했습니다. 실제 합성기 연결 검사는 로컬 Noto 폰트를 사용한 기능 검사이며 게임 글꼴의 외형 검증을 대신하지 않습니다. **확장 출력층의 Windows GPU 학습·실제 게임 폰트·운영 서버 배포/등록은 이번 변경에서 실행하지 않았습니다.** Windows GPU에서 확장 가중치 저장·재로딩·새 문자 인식과 실제 배경 예시를 확인해야 합니다.

CER·편집거리 코드는 ldb-ocr의 순수 계산 모듈에서 가져왔습니다. 원저작자는 blahaj94 및 LDB 기여자이며 원 출처는 [LDB PR #500](https://github.com/blahaj94/ldb/pull/500)입니다. 별도 라이선스를 임의로 부여하지 않습니다. 모델·PaddleOCR 소스·GPU 가상환경·실제 정답 데이터는 앱 배포 파일과 Git에 포함하지 않습니다.
