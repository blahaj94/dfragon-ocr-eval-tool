# 문자 검사

학습 결과의 문자 사전과 `labels.json` 정답을 대조합니다. 모델 가중치·이미지·GPU를 사용하지 않습니다.

```sh
pnpm install
pnpm dev
```

1. **문자 검사** 탭에서 학습 결과 폴더와 `labels.json`을 선택합니다.
2. **문자 포함 검사**를 누릅니다.
3. 고유 문자 수·사전 포함 수·누락 수·포함률을 확인합니다.
4. 기본 **누락 문자** 목록 또는 **전체 문자**에서 등장 횟수와 사전 포함 여부를 봅니다.

포함률은 **사전에 포함된 고유 문자 수 / 전체 고유 문자 수**입니다. 빈 정답 목록은 **검사 대상 없음**, 읽기·설정 오류는 **검사 실패**로 구분합니다. **누락 없음**은 문자 포함 여부만 의미하며 OCR 정확도나 전체 학습 준비 상태를 판정하지 않습니다.

Unicode 코드 포인트 단위로 원문을 셉니다. 반복 등장한 문자는 빈도에 모두 반영하며 trim·정규화·치환을 하지 않습니다. 공백과 보이지 않는 문자는 표시 이름과 코드 포인트로 확인할 수 있습니다. 문자 종류는 보조 표시이며 기타 문자도 빠짐없이 검사합니다.

## 필요한 파일

지원하는 ldb-ocr 학습 결과 폴더의 `request.json`, `config.yml`, `characters.txt`와 정답 `labels.json`만 읽습니다. 설정의 사전 경로·공백 정책·사전 해시가 일치해야 합니다. 누락되거나 지원하지 않는 설정을 기본 사전으로 대체하지 않습니다.

현재 지원 형식은 `schemaVersion: 1`, `v5-korean` 또는 `v6-small-ko` 모델의 `smoke`·`korean` 학습 결과입니다. 기록된 사전 경로의 관계와 선택한 사전의 해시를 검증하므로 필요한 텍스트 파일만 복사한 폴더에서도 검사할 수 있습니다. 실제 평가 실행의 경로 제약과는 별개입니다.

기존 로더처럼 사전은 UTF-8 한 줄에 문자 하나이며 줄바꿈만 제외합니다. `useSpace`가 켜져 있으면 실제 공백 U+0020을 포함합니다. CTC blank는 내부 기호이므로 정답 문자로 세지 않습니다. 중복 문자나 한 코드 포인트가 아닌 항목은 잘못된 사전으로 표시합니다.

정답 형식은 [기존 labels.json](guide.md#라벨과-캡처-형식)을 따릅니다. 이 화면에서는 빈 `samples` 배열을 허용하며 PNG·metadata의 존재 여부는 확인하지 않습니다. 캡처 루트·Python·체크포인트 선택도 필요하지 않습니다.

원본 정답·사전·설정을 수정하지 않습니다. 결과는 화면에만 표시하며 검사 이력이나 내보내기 파일은 만들지 않습니다. 모델 가중치와의 호환성은 이 검사 범위에 포함되지 않습니다.
