# Dataset 관리

같은 캡처 이벤트의 ROI를 한 묶음으로 골라 **train(공부) / val(연습시험) / test(최종시험)**에 배정합니다. 정답 목록에 등록된 ROI만 다루며 원본 PNG와 라벨은 복사·이동·수정하지 않습니다.

## 실행

기존 앱에서 **Dataset** 탭을 엽니다.

```sh
pnpm install
pnpm dev
```

검사에는 Python 3.12와 Pillow가 필요하며 GPU나 OCR 모델은 사용하지 않습니다. 기존 Python 환경을 선택하거나, 이 저장소의 고정된 의존성으로 별도 환경을 준비합니다.

```sh
uv sync --project python
uv run --project python python -c "import sys; print(sys.executable)"
```

화면의 Python 항목에 출력된 실행 파일을 선택합니다.

## 사용

1. Python 실행 파일, Cropper 캡처 루트, `labels.json`을 선택하고 **데이터 불러오기**를 누릅니다.
2. 캡처 이벤트를 선택하고 train / val / test에 배정합니다. 확정 전에는 미배정으로 되돌릴 수 있습니다.
3. **Dataset 검사**로 문제 목록을 확인합니다. 배정을 바꾸면 다시 검사해야 합니다.
4. 통과한 배정을 **배정 확정**으로 저장합니다. 확정한 train / val / test 배정은 변경할 수 없습니다.
5. 내보내기 폴더를 선택해 **Dataset 내보내기**를 실행합니다.

화면의 개수와 내보내기 대상은 **현재 선택한 캡처 루트**입니다. 다른 캡처 루트를 불러와도 기존 확정 기록과 이미지 지문을 유지하고, 용도 간 중복 검사에 함께 사용합니다. 새 항목은 미배정으로 추가하며 목록에서 제외합니다. 기존에 확정된 이벤트에 새 ROI가 추가되면 같은 용도로만 확정할 수 있습니다.

앱을 다시 열면 확정 기록과 마지막 캡처 선택을 복원합니다. 확정하지 않은 임시 배정은 저장하지 않습니다.

이전에 불러온 미배정 항목도 기록에 남습니다. 아직 확정하지 않은 항목을 배정하려면 현재 선택한 `labels.json`에도 해당 항목이 있어야 합니다.

## 검사와 저장

검사는 읽기 전용 `python/dataset_check.py`에서 실행합니다.

- 파일 누락, 열 수 없는 PNG, 잘못된 라벨·Cropper 캡처 정보는 오류입니다.
- 디코딩한 크기와 RGBA 픽셀이 같은 이미지는 이름이나 PNG 압축 방식이 달라도 중복으로 판단합니다. 같은 용도 안에서는 경고, 다른 용도 사이에서는 오류입니다.
- 같은 캡처 이벤트 또는 같은 캡처 원본의 ROI가 다른 용도로 나뉘면 확정할 수 없습니다.
- 검사 실행 실패와 잘못된 JSON 응답은 통과가 아닙니다. 확정 직전에 입력을 다시 확인하고, 기록 저장에 성공해야 확정 상태를 표시합니다.

분할 기록은 앱 데이터 폴더의 `dataset-splits.json` 하나에 저장합니다. 정확한 경로는 화면에서 확인할 수 있습니다. 기존 확정 정보와 디코딩한 이미지의 해시를 보관하므로, 이름을 바꿔 다시 가져온 이미지도 비교합니다.

내보내기는 매번 새 하위 폴더를 만들며 이전 목록을 덮어쓰지 않습니다.

```text
새 내보내기 폴더/
├── train-labels.json
├── val-labels.json
└── test-labels.json
```

각 파일은 [기존 labels.json 형식](../examples/labels.json)인 `schemaVersion: 1`과 `samples` 배열을 사용하며, 항목에는 `id`, 캡처 루트 기준 `image` 상대경로, `truth`가 들어갑니다. 해당 용도로 확정된 항목만 포함합니다. 비어 있는 용도의 목록은 빈 배열이며 평가 앱에서 평가할 샘플은 없습니다.

보호 대상은 이 관리 앱의 확정 기록과 생성하는 목록입니다. 기존 학습 프로그램에는 검사를 연결하지 않으며, 앱 밖에서 직접 파일을 섞는 행위까지 막지는 않습니다.

## 검증

작은 PNG 자료로 정상 검사·확정, 누락 파일·용도 간 중복 차단, 검사 실행 실패, 저장 실패 시 확정 방지, 재실행 복원, 확정 항목만 내보내기를 확인했습니다. 전체 Vitest 20개, Python 42개, Playwright 12개와 lint·format·typecheck·build를 통과했습니다.

실제 Windows Electron 앱에서도 PNG 4개를 train 2 / val 1 / test 1로 확정하고, 앱 재실행 후 세 목록 저장까지 확인했습니다. 원본 PNG·metadata·라벨의 바이트 해시는 전후 동일했습니다. 대규모 실사용 데이터셋은 검증하지 않았습니다.
