# 기존 평가 결과 A/B 비교

**결과 비교** 탭에서 이미 저장한 평가 보고서 두 개를 비교합니다. 모델·Python·GPU를 실행하지 않습니다.

```sh
pnpm install
pnpm dev
```

## 사용

1. **결과 비교** 탭을 엽니다.
2. **A 보고서 선택**으로 기준 모델의 `report.json`을 선택합니다.
3. **B 보고서 선택**으로 후보 모델의 `report.json`을 선택합니다.
4. **보고서 비교**를 누릅니다.
5. 저장된 CER, 완전 일치율, 완전 일치 수 / 전체 샘플 수를 나란히 확인합니다.
6. 그룹을 전환하고 이미지를 눌러 확대합니다. 정답과 A·B 예측, 각각의 저장된 편집거리를 함께 봅니다.

| 그룹                  | 기준 A | 후보 B |
| --------------------- | ------ | ------ |
| 새로 틀림 — 기본 보기 | 성공   | 실패   |
| 새로 맞힘             | 실패   | 성공   |
| 둘 다 성공            | 성공   | 성공   |
| 둘 다 실패            | 실패   | 실패   |

성공은 예측 문자열과 정답이 완전히 같은 경우입니다. 공백을 자르거나 문자열을 정규화하지 않습니다. 앱은 어느 모델이 더 좋은지나 배포 가능 여부를 판정하지 않습니다.

## 비교 조건

현재 앱의 `schemaVersion: 1` 보고서 두 개가 모두 `completed`여야 합니다. 고유한 샘플 ID로 연결하며, 전체 ID 집합·각 이미지의 `imageSha256`·정답이 모두 같아야 합니다. 샘플 배열 순서나 캡처 폴더의 절대 경로가 달라도 비교할 수 있습니다. 일부 샘플만 골라 비교하지 않습니다.

보고서의 정규화 정책은 `none`이어야 하며, `reproducibility.sourceSha256`에 저장된 `recognition/metrics.py`와 `recognition/distance.py` 해시가 양쪽에서 같아야 합니다. 모델·체크포인트·전처리 설정이 다른 것은 허용합니다. 저장된 성적을 표시하며 편집거리나 CER를 새로 계산하지 않습니다.

필요한 이미지 해시·평가 기준 정보·완전 일치 수가 없는 이전 보고서는 제한 사유를 표시합니다. 값을 추측하거나 재평가하지 않습니다. 현재 보고서의 이미지 해시는 **PNG 파일 바이트** 기준이므로, 픽셀이 같아도 다시 인코딩해 파일 해시가 달라진 경우에는 같은 평가 대상으로 인정하지 않습니다.

## 이미지와 파일

이미지는 보고서에 기록된 A 또는 B의 경로에서 찾습니다. 기록된 캡처 루트 안에 있고 저장된 이미지 해시와 일치하는 PNG만 표시합니다. 파일이 없어졌거나 바뀌었다면 이미지 오류를 표시하며, 저장된 성적과 텍스트 비교는 계속 볼 수 있습니다.

확대는 화면 표시용입니다. 원본 보고서·PNG·라벨·체크포인트를 수정하지 않으며 비교 결과·이력·내보내기 파일도 만들지 않습니다.
